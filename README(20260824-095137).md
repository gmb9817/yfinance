# 다음 거래일 주가 방향 예측기 — Colab Notebook

`stock_direction_80_colab.ipynb`는 `yfinance` 일봉 데이터를 이용해 다음 거래일 종가의 상승·하락을 연구하는 Colab/Jupyter 노트북이다.

기존 `.py` 버전의 명령행 인자 처리를 제거하고, 노트북 맨 위의 설정 셀에서 종목·기간·모드·목표 정확도를 직접 바꾸도록 재구성했다. 따라서 Colab이 자동으로 전달하는 `-f kernel-....json` 인자 때문에 발생하던 오류가 없다.

이 프로젝트는 모든 거래일에 방향을 강제로 출력해 80%를 주장하지 않는다. 여러 모델의 방향 예측과 별도의 메타 선택기를 이용해 신뢰도가 높은 날만 선택하고, 손대지 않은 최종 테스트 구간에서 선택 정확도·선택 비율·신호 수·신뢰구간을 함께 검증한다.

## fast와 full의 차이

### fast

- 패널 종목 수를 줄인다.
- 학습창 후보 수를 줄인다.
- 트리 모델의 반복 수를 줄인다.
- XGBoost를 사용하지 않는다.
- 코드 구조와 데이터 다운로드가 정상인지 확인하는 데 적합하다.

### full

- 더 많은 패널 종목을 사용한다.
- 756일, 1260일, 1890일, 확장형 학습창을 비교한다.
- Extra Trees와 Histogram Gradient Boosting의 반복 수를 늘린다.
- XGBoost가 설치되어 있으면 앙상블에 추가한다.
- 최종 연구 결과를 확인할 때 사용한다.

`fast` 결과와 `full` 결과가 반드시 같은 방향이나 정확도를 보이는 것은 아니다.

## 80% 판정 기준

### `passed_80`

다음 조건을 모두 만족해야 한다.

```text
선택 정확도 >= TARGET_ACCURACY
선택 신호 수 >= MIN_TEST_SIGNALS
선택 비율 >= MIN_COVERAGE
상승 신호 수 >= MIN_SIDE_SIGNALS
하락 신호 수 >= MIN_SIDE_SIGNALS
```

### `certified_80`

`passed_80`에 더해 선택 정확도의 Clopper–Pearson 신뢰구간 하한도 `TARGET_ACCURACY` 이상이어야 한다.

예를 들어 20개 신호 중 16개를 맞히면 점추정 정확도는 80%지만 표본이 적어서 신뢰구간이 넓다. 따라서 `passed_80`은 참일 수 있어도 `certified_80`은 거짓일 수 있다.

최신 상승·하락 방향은 `certified_80`이 참이고 최신 선택 점수도 임계값 이상인 경우에만 허용된다. 그 외에는 `관망`을 출력한다.

## 결과를 읽는 순서

1. `majority_baseline`과 `forced_accuracy`를 비교한다.
2. `selective_accuracy`와 `coverage`를 함께 확인한다.
3. `signals`, `up_signals`, `down_signals`를 확인한다.
4. `selective_lower`와 `selective_upper`로 불확실성을 확인한다.
5. `passed_80`, `certified_80`을 확인한다.
6. 마지막으로 최신 `decision`을 본다.

### 좋은 결과의 예

```text
강제 정확도: 기준선보다 높음
선택 정확도: 80% 이상
선택 비율: 최소 조건 이상
선택 신호: 충분함
상승·하락 신호: 모두 존재
신뢰구간 하한: 80% 이상
```

### 주의가 필요한 결과의 예

```text
선택 정확도: 90%
선택 신호 수: 10개
선택 비율: 3%
신뢰구간 하한: 60%
```

이 경우 정확도 숫자는 높지만 표본과 선택 비율이 부족하므로 80%가 입증된 것이 아니다.

## 자주 발생하는 오류

### `unrecognized arguments: -f ...kernel...json`

이 노트북 버전에는 `argparse`와 `parse_args()`가 없다. 설정 셀에서 값을 직접 지정하므로 해당 오류가 발생하지 않는다.

### 대상 종목 데이터를 받지 못함

다음을 확인한다.

- 종목 코드 오타
- 한국 종목의 `.KS` 또는 `.KQ` 접미사
- Yahoo Finance에서 제공되는 종목인지 여부
- 일시적인 네트워크 또는 Yahoo 응답 문제

셀을 다시 실행했는데도 대상 종목이 계속 실패하면 다른 시작일이나 종목 코드로 확인한다.

### 패널 종목이 4개 미만

여러 보조 종목 다운로드가 실패한 상태다. 네트워크를 확인하고 데이터 다운로드 셀부터 다시 실행한다.

### 거래일이 부족함

`START`를 더 과거로 설정하거나 다음 값을 줄여야 한다.

- `TEST_DAYS`
- `OOF_DAYS`
- `MIN_TRAIN_DAYS`

값을 너무 줄이면 실험의 신뢰성이 낮아질 수 있다.

### 워크포워드 폴드가 3개 미만

`START`를 더 과거로 설정하거나 `OOF_DAYS`, `MIN_TRAIN_DAYS`, `FOLD_DAYS` 조합을 조정한다.

### XGBoost 관련 설치 오류

먼저 런타임을 재시작한 뒤 설치 셀을 다시 실행한다. XGBoost를 제외하고 구조만 확인하려면 `MODE = "fast"`를 사용한다.

### 메모리 부족

다음 순서로 규모를 줄인다.

1. `MODE = "fast"`
2. `OOF_DAYS` 감소
3. `TEST_DAYS` 감소
4. `START`를 최근 날짜로 변경

단, 최종 연구에서는 충분한 기간을 다시 확보해야 한다.

### `80%가 미검증되어 실전 배포 금지`

프로그램 오류가 아니다. 독립 테스트에서 목표를 충족하지 못했거나 표본 수·선택 비율·신뢰구간 조건이 부족하다는 뜻이다.

- 실패한 실험도 삭제하지 않고 남긴다.
- 정확도만 기록하지 않고 선택 비율과 신호 수를 함께 기록한다.
- 수수료와 슬리피지를 포함한 투자 백테스트는 방향 분류 평가와 별도로 수행한다.
- 장 마감 후 확정된 데이터로 같은 조건에서 다시 실행한다.

## 한계

- 일봉 OHLCV와 공개 시장 데이터만으로 모든 시기와 종목에서 80%를 보장할 수 없다.
- 선택 정확도가 높아져도 선택 비율이 낮아질 수 있다.
- Yahoo Finance 데이터 지연, 누락, 수정에 영향을 받을 수 있다.
- 분류 정확도가 높아도 거래 비용을 고려한 수익이 높다는 보장은 없다.
- 특정 시장 국면에서 얻은 패턴이 다른 국면에서 사라질 수 있다.
- 테스트 구간을 반복적으로 확인하면 실제로는 테스트 데이터에 과적합하게 된다.

이 프로젝트의 목적은 80%라는 숫자를 강제로 출력하는 것이 아니라, 목표가 실제로 독립 구간에서 재현되는지 정직하게 판정하는 것이다.
